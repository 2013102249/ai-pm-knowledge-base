# 全局术语表（跨章去重定向）

> **用法**：本表是全库术语的唯一口径。章内术语表按当周语境给场景化解释，冲突时以本表为准。共 **122 条**，分 9 类；「主要章节」指首次系统讲解的位置。

## A. 基础与模型（18 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| AI 产品经理 | AI PM | 负责 AI 能力产品化、效果可度量、成本与合规可控的产品负责人 | 不是算法工程师，也不是「会写提示词的产品助理」 | W1D1 |
| 基础模型 / 大模型 | Foundation Model / LLM | 经大规模数据预训练、可适配多任务的模型 | 「大模型」不等于「万能」，能力有明确边界 | W1D2 |
| 参数量 | Parameters | 模型内部可学习权重的规模，常以 B（十亿）计 | 参数量大不必然效果好，需看评测与场景 | W1D2 |
| Token | Token | 模型处理文本的最小计费与计算单位，不等同于汉字或单词 | 中文 1 字常对应 1–2 Token，估算要留余量 | W1D2 / W5D3 |
| 上下文窗口 | Context Window | 单次请求可携带的上下文总量上限 | 超出会被截断，不等于模型「记住了」全部历史 | W1D2 / W1D3 |
| 概率式生成 | Probabilistic Generation | 模型按概率逐 Token 生成，故同一输入可有不同输出 | 「输出不稳定」是特性，需要评测与兜底管理 | W1D2 |
| 幻觉 | Hallucination | 模型生成看似合理但与事实或输入不符的内容 | 不能靠「提示词写严一点」根治，需 RAG/引用/校验 | W1D2 / W4D3 |
| 知识截止 | Knowledge Cutoff | 训练数据的时间边界，之后的事实模型可能不知道 | 与「联网搜索」是两回事，后者属工具能力 | W1D2 / W2D1 |
| 推理 | Inference | 训练完成后用模型产出结果的过程 | 与「逻辑推理能力」不同，前者是工程动作 | W1D2 |
| 预训练 | Pre-training | 在大规模语料上学习通用表示的阶段 | 成本极高，产品团队通常不参与 | W2D2 |
| 监督微调 | SFT | 用标注问答对调整模型行为与风格 | 不能凭空补进私有事实，事实优先用 RAG | W2D2 |
| 参数高效微调 | LoRA / PEFT | 只训练少量附加参数以低成本适配模型 | 适合风格与格式，不适合高频更新的知识 | W2D2 |
| 人类反馈强化学习 | RLHF | 用人类偏好信号对齐模型输出 | 属对齐方法，不是「让模型记住业务数据」 | W2D2 |
| 蒸馏 / 量化 | Distillation / Quantization | 用小模型继承能力 / 降低数值精度以省资源 | 都会带来质量损失，需评测验证 | W2D2 |
| 多模态 | Multimodal | 处理文本、图像、音频、视频等两种以上模态 | 「支持上传图片」不等于「理解图片」 | W3D4 |
| 向量表示 | Embedding | 把文本等映射为向量以便相似度检索 | 相似度不等于语义正确，需重排与阈值 | W3D3 |
| 温度参数 | Temperature | 控制生成随机性的采样参数 | 调低只降低波动，不消除幻觉 | W1D2 |
| 模型版本 | Model Version | 供应商发布的具体模型标识与快照 | 版本混用会污染 AB 实验与评测结论 | W2D1 / W5D2 |

## B. 提示词与上下文（12 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 提示词 | Prompt | 传给模型的指令、上下文与约束的集合 | 不只是「一句话咒语」，是产品规格的一部分 | W1D3 |
| 提示词工程 | Prompt Engineering | 设计指令结构以提升单次输出质量的方法 | 关注「怎么说」，不解决「给什么信息」 | W1D3 |
| 上下文工程 | Context Engineering | 系统性决定「哪些信息、以什么顺序、占多少预算进入上下文」 | 是产品与工程能力，不是话术技巧 | W1D3 |
| 系统提示词 | System Prompt | 定义角色、边界与输出规则的高优先级指令 | 与用户消息权限不同，仍可能被注入绕过 | W1D3 / W2D4 |
| 少样本示例 | Few-shot | 在提示词中给出若干示例引导输出格式 | 示例占上下文预算，也会引入偏见 | W1D3 |
| 思维链 | CoT | 让模型显式写出中间推理步骤的提示技巧 | 展示的「推理」不等于可验证的逻辑 | W1D3 |
| 上下文预算 | Context Budget | 窗口内为指令/知识/历史/输出预留的额度分配 | 只算输入不算输出会导致截断 | W1D3 |
| 上下文压缩 | Context Compaction | 摘要、裁剪、去重以控制上下文长度 | 压缩会丢信息，关键约束应保留原文 | W1D3 / W5D3 |
| 输出格式约束 | Output Schema | 用 JSON/表格等结构化约定约束输出 | 需要解析器与校验，不能只靠提示词 | W1D3 / W4D2 |
| 提示词注入 | Prompt Injection | 用户输入或外部内容挟持模型指令的攻击 | 属安全风险，不只是「输出不听话」 | W2D4 |
| 提示词版本管理 | Prompt Versioning | 对提示词做版本、评测与回滚管理 | 与代码版本同等重要，影响可复现性 | W5D4 / W5D2 |
| 模板 | Template | 可复用、带占位符的提示词/文档骨架 | 模板要带验收标准，否则只是格式 | W1D3 / W4D2 |

## C. Agent 与 RAG（18 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 智能体 | Agent | 能规划、调用工具、基于反馈迭代以达成目标的系统 | 与固定工作流区别在「决策权」而非「步骤数」 | W3D1 |
| 工作流 | Workflow | 预先定义的、按固定顺序执行的步骤编排 | 更可控、更便宜，优先于高自主度 Agent | W3D1 / W3D2 |
| ReAct | Reason + Act | 推理—行动—观察循环的经典 Agent 范式 | 循环需设最大步数，否则成本失控 | W3D1 |
| 规划 | Planning | 把目标拆成可执行子任务的过程 | 拆分质量决定后续工具调用是否可验收 | W3D1 |
| 记忆 | Memory | 短期会话状态与长期可检索信息的统称 | 长期记忆通常靠外部存储，不是模型自带 | W3D1 / W3D3 |
| 工具调用 | Tool / Function Calling | 模型按契约调用外部 API 或函数 | 契约必须定义失败与权限，不只是参数 | W3D2 |
| 反思 | Reflection | 对执行结果自检并修正的环节 | 会增加延迟与 Token，需设触发条件 | W3D1 |
| 自主度等级 | Autonomy Level | L0 固定流程到 L3 自主规划的产品分级 | 等级越高≠越好，取决于失败代价 | W3D1 |
| 人工确认点 | Human-in-the-loop | 在关键动作前插入人工审批或确认 | 位置比数量重要，应卡在不可逆动作前 | W3D2 |
| MCP | Model Context Protocol | 让模型以统一方式接入外部工具与数据的协议 | 是接口约定，不等于具体工具实现 | W3D2 |
| 检索增强生成 | RAG | 先从知识库检索证据，再让模型基于证据生成 | 不改动模型权重，与微调互补 | W3D3 |
| 切片 | Chunking | 把文档切成可检索片段 | 切片过大/过小都会影响召回质量 | W3D3 |
| 向量检索 | Vector Retrieval | 按语义相似度召回候选片段 | 相似度高分不代表答案正确 | W3D3 |
| 重排 | Reranking | 对召回结果二次排序以提升相关性 | 与召回是两个阶段，指标也不同 | W3D3 |
| 召回率 | Recall | 相关证据被检索到的比例 | 高召回不等于高答案正确率 | W3D3 / W2D3 |
| 引用溯源 | Citation / Grounding | 答案标注来源片段，便于核查 | 有引用仍需校验引用是否支持结论 | W3D3 |
| 图谱 RAG | GraphRAG | 借助知识图谱处理跨文档全局性问题 | 构建与维护成本高于普通向量检索 | W3D3 |
| 知识库产品 | Knowledge Base Product | 面向用户的文档接入、更新、权限与问答产品 | 「传了文档」不等于「能正确回答」 | W3D3 |

## D. 评测与合规（16 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 评测集 | Eval Set | 带期望结果与评分点的测试样本集合 | 不是随便攒的问答，需分层与边界用例 | W2D3 |
| 黄金集 | Golden Set | 经人工确认、作为基准的高质量评测集 | 会过时，需随产品更新维护 | W2D3 |
| 回归集 | Regression Set | 每次改动都重跑、防止改坏既有能力的子集 | 与新增用例分开管理 | W2D3 / W6D4 |
| 忠实度 | Faithfulness | 答案是否忠实于给定证据 | 与「事实正确」不同：证据错则忠实也可能错 | W2D3 |
| 幻觉率 | Hallucination Rate | 无依据生成内容在样本中的占比 | 统计口径必须写清，否则不可比 | W2D3 / W4D4 |
| 人工偏好评估 | Human Preference | 由评审员对输出做成对比较或打分 | 需评分规范与一致性检查 | W2D3 |
| 离线评测 | Offline Eval | 上线前用固定数据集跑批评估 | 不能替代真实用户反馈 | W2D3 / W6D4 |
| 在线评测 | Online Eval | 用线上流量、反馈与指标持续评估 | 与 AB 实验配合，注意模型版本污染 | W2D3 / W5D2 |
| 红队测试 | Red Teaming | 主动构造攻击/越界输入检验系统韧性 | 不只测内容安全，也测越权与泄露 | W2D4 |
| 护栏 | Guardrails | 输入/输出侧的约束、过滤与拦截机制 | 是工程组件，不是一句合规声明 | W2D4 |
| 可观测性 | Observability | 记录调用链、上下文、成本与结果以便追溯 | 有日志≠可观测，需可查询与关联 | W5D4 / W6D4 |
| 内容安全 | Content Safety | 对违法违规与不当内容的识别与处置 | 与「数据合规」是两条不同工作线 | W2D4 |
| 算法/大模型备案 | Filing / Registration | 国内对具有舆论属性或社会动员能力的算法与生成式服务的备案要求 | 属合规流程，名称与要求以官方最新发布为准 | W2D4 |
| 生成合成内容标识 | Content Labeling | 对 AI 生成内容作显式或隐式标识的要求 | 需在产品设计阶段预留字段与展示位 | W2D4 |
| 个人信息处理 | PII Processing | 收集、存储、使用用户个人信息的全过程 | 训练数据与日志同样受约束 | W2D4 |
| 数据合规 | Data Compliance | 数据来源、授权、跨境、留存与删除的合规管理 | 供应商合规不免除产品方责任 | W2D4 |

## E. 产品与需求（14 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 产品需求文档 | PRD | 描述问题、方案、验收与约束的可评审文档 | AI 产品的 PRD 必须含评测线与兜底 | W4D2 |
| 最小可行产品 | MVP | 用最小范围验证核心价值假设的可运行版本 | 不是「功能少」，是「假设明确」 | W6D2 |
| 用户研究 | User Research | 通过访谈、观察等理解用户任务与痛点 | 用户常无法直接描述「想要什么 AI」 | W4D1 |
| 任务待办 | JTBD | 从「用户雇产品完成什么任务」定义需求 | 与功能清单不是一回事 | W4D1 |
| AI 必要性判据 | AI Necessity Test | 判断不用 AI 是否也能解决、用 AI 是否明显更优 | 防止为了用 AI 而用 AI | W4D1 |
| 验收标准 | Acceptance Criteria | 可观测、可判定是否达标的验收条件 | 「效果更好」不是验收标准 | W4D2 |
| 非目标 | Non-goals | 明确本次不做什么，防止范围蔓延 | 与「后续再做」要分开写 | W4D2 / W2D5 |
| 异常兜底 | Fallback | 失败或不确定时的用户可见表现与替代路径 | 兜底不是隐藏错误，而是给出可用结果 | W4D3 |
| 降级策略 | Degradation | 换模型、转规则、转人工等有损但可用的备选链路 | 需预先定义触发条件与埋点 | W4D3 |
| 置信度展示 | Confidence Display | 向用户呈现结果可靠程度与不确定性 | 分数若无校准，反而误导用户 | W4D3 / W3D4 |
| 用户旅程 | User Journey | 用户从进入到完成任务的端到端路径 | AI 产品需额外标注等待与纠错节点 | W3D2 / W6D3 |
| 产品形态 | Product Form | Chat / Copilot / Agent / 嵌入式 / AI 原生的交互范式 | 形态决定确定性要求与成本结构 | W1D4 |
| 方案设计 | Solution Design | 把需求转成流程、模块与约束的设计过程 | 与「写提示词」不是同一层级 | W4D3 |
| 评审 | Review | 由多角色按清单对交付物做判定并留痕 | 评审结论要可追踪到修改动作 | W3D5 / W4D5 |

## F. 数据与增长（14 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 北极星指标 | North Star Metric | 最能代表产品核心价值的一个指标 | 不等于营收，也不等于调用量 | W4D4 / W5D1 |
| 护栏指标 | Guardrail Metric | 不能为提升主指标而恶化的约束性指标 | AI 场景必含成本、延迟、投诉/幻觉率 | W4D4 / W5D2 |
| 日活跃用户 | DAU | 当日完成定义行为的去重用户数 | 「活跃」定义必须写进埋点文档 | W4D4 |
| 留存 | Retention | 用户在后续周期返回使用的比例 | AI 产品首答失败会显著影响次留 | W4D4 / W5D1 |
| 漏斗 | Funnel | 从进入到完成关键转化的分步序列 | 每一步都要有分母定义 | W4D4 |
| 事件模型 | Event Model | 以「谁在何时做了什么」组织埋点数据 | 与页面 PV 统计不同 | W4D4 |
| 埋点 | Instrumentation | 在关键节点采集行为与结果数据 | 没埋点就无法复盘评测与实验 | W4D4 / W6D4 |
| SQL | SQL | 查询结构化数据的标准语言 | PM 需会读会改，不必会调优 | W4D4 |
| AARRR | AARRR | 获取—激活—留存—收入—推荐的增长框架 | AI 产品需把「每次调用成本」嵌入各环节 | W5D1 |
| 增长飞轮 | Growth Loop | 使用产生数据、数据改进效果、效果带来更多使用的循环 | 需有可度量闭环，不是口号 | W5D1 |
| AB 实验 | A/B Test | 随机分组对照以判断改动因果效果的方法 | 与「前后对比」不同，需对照组 | W5D2 |
| 统计显著性 | Statistical Significance | 观察到差异不太可能由随机波动造成的判断 | 显著不等于业务价值大 | W5D2 |
| 置信区间 | Confidence Interval | 效果估计的不确定范围 | 区间跨 0 时不宜宣称有效 | W5D2 |
| 功能开关 / 灰度 | Feature Flag / Rollout | 按人群或比例控制功能可见性 | 是实验与回滚的基础设施 | W5D2 / W5D4 |

## G. 工程与成本（10 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| Token 成本 | Token Cost | 按输入/输出 Token 计费的可变成本 | 是边际成本，用户越多成本越高 | W5D3 |
| 模型网关 | LLM Gateway | 统一接入多供应商、做计费与治理的中间层 | 不等于负载均衡器，含成本与策略 | W5D3 / W2D1 |
| 模型路由 | Model Routing | 按难度把请求分给不同成本的模型 | 需评测兜底，避免简单问题被误判 | W2D1 / W5D3 |
| 缓存 | Caching | 复用相同/相似请求结果以降本提速 | 会影响实验分组与个性化结果 | W5D3 / W5D2 |
| 限流 | Rate Limiting | 控制单位时间调用量以保护预算与稳定性 | 需给用户可读的提示与重试策略 | W5D3 / W4D3 |
| P95 延迟 | P95 Latency | 95% 请求在该时间内完成 | 平均值会掩盖长尾体验问题 | W4D4 / W5D2 |
| LLMOps | LLMOps | 面向大模型应用的版本、评测、监控与迭代体系 | 比传统 DevOps 多了提示词与评测对象 | W5D4 |
| 调用链追踪 | Trace | 记录一次请求中模型、工具、检索各环节 | 是定位「哪一步错了」的前提 | W5D4 / W6D4 |
| 模型供应商 | Model Provider | 提供模型 API 服务的一方 | 其合规资质不替代产品方责任 | W2D4 |
| 服务等级协议 | SLA | 对可用性与性能的承诺 | 大模型服务常有波动，需设计降级 | W4D3 |

## H. 项目与协作（10 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 里程碑 | Milestone | 以交付物与验收为标志的阶段节点 | 不是「时间到了」就算完成 | W2D5 |
| 交付物 | Deliverable | 可被评阅的具体产物（文档、原型、报告等） | 必须可检查，不能是「讨论过」 | W2D5–W6D5 |
| RACI | RACI | 负责/批准/咨询/知会的角色分工表 | 一个任务只能有一个 A | W5D4 |
| 变更单 | Change Request | 记录范围、原因、影响与批准的需求变更 | 口头变更会让评测与验收失效 | W5D4 |
| 风险看板 | Risk Board | 记录风险、概率、影响、责任人与应对动作 | 要定期更新，不是一次性表格 | W5D4 |
| 站会 | Standup | 短周期同步进展与阻塞的会议 | 不用于讨论方案细节 | W6D2 |
| 范围裁剪 | Scope Cut | 在时间不足时按价值与依赖缩减范围 | 先砍非核心路径，不能砍验收线 | W5D5 |
| Vibe Coding | Vibe Coding | 用自然语言规格驱动 AI 生成与修改代码的开发方式 | 不意味着放弃规格与验收 | W6D1 |
| 规格先行 | Spec-first | 先写清目标、约束与验收，再让 AI 执行 | 与「想到哪说到哪」相反 | W6D1 |
| 复盘 | Retrospective | 对目标、过程与结果做结构化回顾 | 要产出可执行的改进项 | W6D5 / W8D2 |

## I. 求职与面试（10 条）

| 术语 | 英文 / 缩写 | 释义 | 易混点 | 主要章节 |
| --- | --- | --- | --- | --- |
| 作品集 | Portfolio | 展示产品判断与证据链的材料集合 | 不是截图合集，需写清决策与取舍 | W7D2 |
| 证据链 | Evidence Chain | 问题—决策—数据—反思的完整叙事 | 缺数据或缺反思都会被追问 | W7D2 / W8D2 |
| STAR | STAR | 情境—任务—行动—结果的行为面试结构 | 「结果」必须是可验证的变化 | W7D3 / W8D2 |
| JD 解析 | JD Mapping | 把岗位关键词映射到可展示的能力证据 | 不是把简历关键词堆满 | W7D5 |
| 投递台账 | Application Tracker | 记录岗位、渠道、状态、跟进与复盘的表 | 用于节奏管理，不是数量竞赛 | W7D5 |
| 转岗叙事 | Career Narrative | 把过往行业经验翻译成产品能力的连贯说明 | 避免「从零开始」式自我贬低 | W7D3 / W8D2 |
| 题型地图 | Question Map | 按项目/场景/技术数据/行为/压力分类的题库结构 | 背答案不如建结构 | W8D1 |
| 压力面 | Stress Interview | 通过质疑、追问、否定检验应变与边界感 | 目标是稳住结构，不是赢辩论 | W8D4 |
| 谈薪 | Compensation Talk | 基于信息与底线协商薪酬与整体包的沟通 | 不写具体数字，讲区间与替代项 | W8D5 |
| 30/60/90 计划 | 30-60-90 Plan | 入职后分阶段的目标与学习行动计划 | 也可用于结营后的求职节奏管理 | W8D5 |

> **收尾类比**：术语表像厨房里的调料标签——不写清楚，同一瓶「少许」在不同人手里就是三道不同的菜；统一口径之后，讲师、学员和面试官才尝得到同一个味道。
